How it works

Three ways to serve. Zero ways to care.

Point any OpenAI client at localhost:9337/v1 and stop caring where the work actually happens. Meshpool picks the best path for every request.

1

Run locally

If this machine's GPU can handle the model, the request never leaves the box. Lowest latency, zero network hops.

2

Route to a peer

A peer already has the model warm in memory? The request is routed straight to it over an encrypted p2p connection.

3

Split across machines

A model too big for any single box is sharded across several machines as a pipeline — a 235B model on hardware you already own.

Drop-in API

Why Meshpool

Built for the hardware you actually have.

Most teams' GPUs sit idle 60–70% of the time, scattered across providers and desks. Meshpool turns that fragmentation into capacity.

Heterogeneous by design

Mix data-center cards, gaming GPUs, and Apple silicon in one pool. Meshpool schedules around what each box can do.

Private by default

End-to-end encrypted peer connections. Your prompts, weights, and outputs never touch infrastructure you don't control.

Zero-config networking

Built on iroh. Nodes find each other through NATs and firewalls — no VPN, no port forwarding, no YAML archaeology.

One endpoint, anywhere

Every node exposes the same API. Your app talks to localhost; the mesh handles discovery, routing, and failover.
